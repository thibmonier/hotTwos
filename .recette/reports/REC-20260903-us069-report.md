## Findings

### F1 — Seed démo ne rendait pas Marc responsable → `/validation` toujours vide *(CORRIGÉ dans ce lot)*
`SeedDemoDataCommand::seedProjects` créait ALPHA/BETA **sans `responsibleUserId`**. `findByResponsible(marc)`
renvoyait `[]` → `/validation` affichait « aucun projet » quelles que soient les imputations. C'est pourquoi
la validation peuplée n'avait **jamais** pu être recettée. **Correctif** : Marc responsable des deux projets
dans le seed (ses imputations en attente alimentent l'écran).

### F2 — Valorisation non démontrable : seed sans profils ni tarifs *(À BACKLOGUER)*
`profile = 0`, `profile_rate = 0`, `fact_project_revenue = 0`. Sans profils/tarifs, aucun revenu n'est
calculé même sur les 5 imputations validées → l'écran reste à « 0,00 € / 0/0 ». Enrichir le seed
(profils + tarifs + assignations + recalcul des revenus) pour rendre la valorisation démontrable — chantier
distinct (modèle finance), à ouvrir en US dédiée ou tâche d'outillage démo.

### F3 — Incohérence d'unité entre écrans *(mineur, observation)*
`/validation` affiche la colonne **« Minutes » (420)** alors que `/saisie` est passée aux **heures décimales**
(US-066). Harmoniser l'unité côté validation (heures « 7h00 » ou décimal) pour la cohérence manager/collaborateur.

### Findings infrastructure (bloquants d'environnement rencontrés)
- **F-INFRA-1** : `make up` casse au build — le `Dockerfile` lance `asset-map:compile` **sans** `tailwind:build`
  avant (« Built Tailwind CSS file does not exist »), contraire à l'ADR-0019 (build Tailwind avant compile).
  Contournement recette : démarrage depuis l'image existante + `make tailwind` au runtime. **À corriger** (OPS).
- **F-INFRA-2** (procédure) : après `app:demo:seed` sur une base modifiée, l'app worker garde des connexions
  DB poolées avec l'ancien contexte tenant (RLS) → `login 401` tant que l'app n'est pas redémarrée
  (`docker compose restart app`). Le cache dev du conteneur doit aussi être reconstruit (`cache:clear`) après
  un pull de code (sinon services périmés, ex. `AccessDeniedExceptionListener`).
- **Hygiène** : la base cumulait 3 tenants de seed (3× `marc@demo.test`) faussant la résolution du login →
  recette relancée sur base purgée (1 tenant). Prévoir un reset propre pour la démo.
